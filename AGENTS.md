# tigris

Ahead-of-time compiler that tiles ONNX and TFLite models to fit a memory budget and emits `.tgrs` binary plans plus C harnesses for the tigris-runtime. Python (floor in `pyproject.toml`), click CLI, setuptools-scm versioning. Public, github.com/raws-labs/tigris; on PyPI as `tigris-ml`.

## Build, test, run
- `pip install -e . --group dev`: editable install with pytest, onnxruntime, ruff, build (dependency groups in `pyproject.toml`, pip 25.1 or later).
- `pytest`: tests under `tests/`; `conftest.py` builds small hand-crafted ONNX graphs, so no model download is needed. `scripts/` is an importable package (has `__init__.py`, and pytest puts the repository root on `sys.path`) because the tests import from it, `conftest.py` included; it is not shipped in the wheel.
- `ruff check src tests scripts setup.py`: rule set is pinned to `E4, E7, E9, F` in pyproject so a ruff upgrade does not change CI policy.
- `python -m build`: source distribution and pure wheel. Native wheels require staging with `scripts/runtime_bundle.py` and `TIGRIS_WHEEL_VARIANT=native`; see `CONTRIBUTING.md`. CI installs both variants outside the checkout and tests their CLI behavior.
- Generated artifacts: `src/tigris/schema/tigris-plan-v<SCHEMA_VERSION>.json` (from `emitters/binary/defs.py`) and `src/tigris/schema/operator-capabilities-v1.json` (from `capabilities.py`). `tests/test_release_compatibility.py` compares each file's text with its generator; `python scripts/generate_schema_package.py --output PATH` and `python scripts/generate_capability_matrix.py --output PATH` rewrite them. `python scripts/generate_operator_contract.py --runtime <path to a tigris-runtime checkout>` writes the runtime's generated headers `src/tigris_op_contract.h` and `src/tigris_op_config.h` from `operator_contract.py`.
- Cross-repo gates, each taking `--runtime <path to a tigris-runtime checkout>`: `scripts/crossrepo_contract.py` (compiler plans executed by the runtime's contract runner against ONNX Runtime, float32 and s8 reference dispatchers only), `scripts/validate_compatibility.py` (`compatibility.json` vs the runtime's `TIGRIS_SCHEMA_VERSION*` macros), `scripts/validate_runtime_capabilities.py` (capability matrix vs the runtime dispatch switches, the runtime's generated operator headers vs the generator, and `defs.py` constants, record sizes, build-limit defaults and the detection scratch formula vs the runtime headers; needs a C compiler). CI runs the contract gate as its own step and the two validators through `tests/test_release_compatibility.py`; it checks out the runtime's `develop`, or a same-named branch when one exists.
- Tests that run TFLite Micro need `tflite-micro` from the `dev` group (Linux x86_64 wheels only); without it they skip, but fail when `CI` is set. `tigris run` on a TFLite model imports the same package at run time.
- `tests/test_frontend_pt2.py`, and the tests of `tests/test_pte_format.py` and `tests/test_pte_model.py` that import torch or executorch, need the `pytorch` group, whose torch pin is PyTorch's CPU build from its own index (install steps in `CONTRIBUTING.md`); without it the tests skip, but fail when `TIGRIS_REQUIRE_PYTORCH` is set. CI runs them in their own job, on one Python version.
- Runtime-dependent tests: `tests/test_codegen_c_syntax.py` compiles generated C against the runtime headers, found through `TIGRIS_RUNTIME_SOURCE` or a sibling `tigris-runtime` checkout; the host-library tests need the library staged in `src/tigris/native` by `scripts/runtime_bundle.py --source <runtime>`. Missing prerequisites skip, but fail when `TIGRIS_RUNTIME_SOURCE` or `CI` is set (headers) or `TIGRIS_REQUIRE_HOST=1` (host library); CI sets all three.
- ExecuTorch program tests (`tests/test_pte_*.py`) read the fixtures in `tests/fixtures/pte/`, written by `scripts/gen_pte_fixtures.py` (needs the `pytorch` group). Four variables enable more, and each test skips without its variable (the tests that also need the `pytorch` group skip without it as well, and fail under `TIGRIS_REQUIRE_PYTORCH`): `TIGRIS_PTE_PROGRAMS`, a directory with `<name>/model.pte` per real program; `TIGRIS_PTE_RUNNER`, a host build of `src/tigris/frontends/pte_host_runner.cpp` (the runner `tigris run` keeps in the user's cache is one); `TIGRIS_EXECUTORCH_SOURCE`, an ExecuTorch checkout with its submodules in a directory named `executorch`, against which the `tigris run` test of `tests/test_pte_host.py` builds that runner (CMake, a C++ compiler, network access for CMSIS-NN, and a Python with torch for the code generator) and checks its outputs under two fills of the planned memory; `TIGRIS_CMSIS_NN_SOURCE`, a CMSIS-NN checkout whose C functions a scratch-size test compiles for the host. `scripts/pte_host_check.py --runner PATH` is the host gate: it exports every fixture in several variants, runs each written program and its original on the runner and fails on any output byte that differs; `--record` rewrites `tests/fixtures/pte/written.json`, which the tests compare export against without a runner.

## CLI
- Subcommands: `analyze` (fit against a budget, `--json` report, `--trace` runs the plan on the host runtime and prints every load, spill and tile), `compile` (binary `.tgrs`, prints the same summary), `codegen` (C from a `.tgrs`), `export` (a TFLite model, or an ExecuTorch program lowered for Cortex-M, rewritten in row bands to run in less RAM; the output is an unchanged copy when nothing lowers it; exit 1 refused, 3 a stated limit not met; `analyze model.pte` prints the same figures without writing), `inspect` (file contents and costs, no compilation; a `.pte` gets its interface and recorded RAM), `run` (on the host, by file identifier: a plan on the TiGrIS host runtime, a TFLite model on the `tflite-micro` package's reference kernels, an ExecuTorch program lowered for scalar or DSP kernels on a host runner built once per commit and set of uncommitted changes of the `--executorch` checkout, with the Python running tigris as ExecuTorch's code generator, and cached; `cli/run.py` holds the engines, `frontends/pte_host.py` the runner build, cache and the `.npy` layout of a method input), `zoo`.
- Output is plain text through `cli/text.py`: click styles, `NO_COLOR` honored, no color off a terminal. One blank line between sections, none before the first.
- Budgets: first `-m` is the fast pool, a second `-m` the slow pool; `-m 256K+4M` is sugar for `-m 256K -m 4M`. `-f/--flash` makes `compile` fail when the plan exceeds it. `--xip` reads weights in place from flash. `-c lz4` compresses weight blocks.
- `codegen --backend reference|esp-nn|cmsis-nn --format app|core`; `--header` and `--name` are valid only with `core`. Accelerated backends are int8 only; a float32 plan on them gets the reference dispatcher explicitly.
- `export --target arm-none-eabi|ilp32|lp64` (default `arm-none-eabi`): the C ABI of the TFLite Micro build whose arena decides whether a rewrite is written. `--cpu`, `--allow-input-overwrite`, `--arena`, `--method`, `--max-extra-macs` and `--header` apply to ExecuTorch programs only; an option given for the other format is a usage error. The shared figures for `export` and `analyze` are formatted in `cli/export.py`.

## Layout
- `src/tigris/frontends/`: TFLite import, converted to the compiler's QDQ ONNX form. `tflite_writer.py` reads a TFLite file into records and writes it back with the FlatBuffers builder; `tflite_export.py` holds the row-band rewrite behind `export`; `tflite_schema.py` holds the schema's field slots and name tables that `tflite.py`, the writer and export share. `tflm.py` models TFLite Micro's arena on reference kernels: `tflm_arena` the planner head, `tflm_persistent` the persistent tail record by record, transcribed from the TFLite Micro sources the dev-group `tflite-micro` is built from; tests compare it with the tail that package measures on each pinned model, so a pin bump that moves one of those tails fails them. `tigris run` gives TFLite Micro the arena `tflite_export.host_arena` sizes: head and tail for the package's build plus `tflm_planning`, a bound of what planning takes past the head, or `tflm_preparing` where a kernel's Prepare takes more; a model the arena model does not cover gets `tflm_bound`, an upper bound that places every tensor and scratch buffer of every subgraph at once. `pt2.py` reads a `torch.export.save` archive through `torch.onnx.export` and measures ExecuTorch's Cortex-M7 arena for `analyze` and `compile`; both need torch, the arena also executorch. `pte_schema.py` and `pte.py` read and write ExecuTorch programs (`.pte`) without torch; `pte_cortex_m.py` holds the cortex_m operator table and CMSIS-NN scratch rules, `pte_method.py` replays the method allocator, `pte_export.py` the row-band rewrite behind `export`, and `pte_check.py` the plan check it runs on every program it writes; `pte_host.py` builds and caches the host runner from `pte_host_runner.cpp`. `src/tigris/loaders/onnx/`: ONNX import; the `normalize/` package holds the pass pipeline for both, one module per concern.
- `src/tigris/analysis/`: lifetime, memory model, temporal partition (stages), spatial partition (tiles, chains, 2D tiling), validation.
- `src/tigris/emitters/binary/`: wire format; `defs.py` is the schema source, `writer.py` and `reader.py` the codecs. `emitters/codegen.py` generates C.
- `src/tigris/capabilities.py`: per-operator backend routes, constraints and conditional fallbacks; the public matrix JSON is generated from it.
- `src/tigris/__init__.py`: `SCHEMA_VERSION` and `SUPPORTED_SCHEMA_VERSIONS` live here. `compatibility.json` records compiler and runtime releases with the schemas each emits or accepts, and entries record each component separately. Paired releases share a version; release ordering and version checks are in `CONTRIBUTING.md`. `tests/schema_compat/` holds a frozen plan for every supported schema version.

## Gotchas
- Normalize pass order is fixed in `normalize()` in `loaders/onnx/normalize/__init__.py`. The loader turns every Constant node into a constant, in subgraphs too, so no pass sees a Constant operator; `shapes.static_value` is the one evaluator for values the graph settles before it runs, used by the load-time fold and `_fold_static_subgraphs`.
- The IR keeps ONNX NCHW/NCL shapes; the runtime executes NHWC/NLC. `_assign_tensor_layouts` in `loaders/onnx/normalize/layout.py` decides each tensor's layout and inserts a Transpose where producer and consumer disagree (rank 3 and 4 only), and `_normalize_concat_axis` restates the Concat axis in that layout. `writer.py` permutes the bytes: Conv weights are transposed, depthwise weights stored HWC, FC weight columns permuted after a Flatten.
- Bumping the plan schema touches `defs.py`, `SCHEMA_VERSION`, a regenerated `src/tigris/schema/tigris-plan-vN.json`, a new frozen plan in `tests/schema_compat/`, and `compatibility.json`. Earlier `tigris-plan-v*.json` files stay in `src/tigris/schema/` as a frozen record of past schemas and ship in the wheel; no test or code reads them, and they are not regenerated.
- The version comes from git tags via setuptools-scm (`src/tigris/_version.py` is generated); a shallow clone reports a wrong version, so CI uses `fetch-depth: 0`.

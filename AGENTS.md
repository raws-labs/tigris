# tigris

Ahead-of-time compiler that tiles ONNX models to fit a memory budget and emits `.tgrs` binary plans plus C harnesses for the tigris-runtime. Python (floor in `pyproject.toml`), click CLI, setuptools-scm versioning. Public, github.com/raws-labs/tigris; on PyPI as `tigris-ml`.

## Build, test, run
- `pip install -e ".[dev]"`: editable install with pytest, onnxruntime, ruff, build.
- `pytest`: tests under `tests/`; `conftest.py` builds small hand-crafted ONNX graphs, so no model download is needed. `scripts/` is an importable package (has `__init__.py`) because `tests/test_release_compatibility.py` imports from it; it is not shipped in the wheel.
- `ruff check src tests scripts`: rule set is pinned to `E4, E7, E9, F` in pyproject so a ruff upgrade does not change CI policy.
- `python -m build`: wheel. CI installs it into a clean venv and runs `tigris --help`.
- Generated artifacts, checked in CI and regenerated by dropping `--check`: `python scripts/generate_schema_package.py --check src/tigris/schema/tigris-plan-v5.json` (from `emitters/binary/defs.py`) and `python scripts/generate_capability_matrix.py --check src/tigris/schema/operator-capabilities-v1.json` (from `capabilities.py`).
- Cross-repo gates, each taking `--runtime <path to a tigris-runtime checkout>`: `scripts/crossrepo_contract.py` (compiler plans executed by the runtime's contract runner against ONNX Runtime, float32 and s8 reference dispatchers only), `scripts/validate_compatibility.py` (`compatibility.json` vs the runtime's `TIGRIS_SCHEMA_VERSION*` macros), `scripts/validate_runtime_capabilities.py` (capability matrix vs the runtime dispatch switches). CI checks out the runtime's `develop`, or a same-named branch when one exists.
- `python scripts/ci_codegen_smoke.py out.c`: reference-backend harness; CI compiles it with `cc -std=c99 -Wall -Wextra -Werror -fsyntax-only -I<runtime>/include`.
- `python scripts/gen_fixtures.py model.onnx -o <dir> [--compress]`: writes `.tgrs` and `.reference.bin` fixtures for the runtime's C tests. There is no `tigris gen-fixtures` subcommand.

## CLI
- Subcommands: `analyze` (feasibility report, no hardware), `plan` (YAML plan), `simulate` (step-by-step execution trace), `compile` (binary `.tgrs`), `codegen` (C from a `.tgrs`).
- Budgets: first `-m` is the fast pool, a second `-m` the slow pool; `-m 256K+4M` is sugar for `-m 256K -m 4M`. `-f/--flash` makes `compile` fail when the plan exceeds it. `--xip` reads weights in place from flash. `-c lz4` compresses weight blocks.
- `codegen --backend reference|esp-nn|cmsis-nn --format app|core`; `--header` and `--name` are valid only with `core`. Accelerated backends are int8 only; a float32 plan on them gets the reference dispatcher explicitly.

## Layout
- `src/tigris/loaders/onnx/`: ONNX import; `normalize.py` holds the pass pipeline.
- `src/tigris/analysis/`: lifetime, memory model, temporal partition (stages), spatial partition (tiles, chains, 2D tiling), validation.
- `src/tigris/emitters/binary/`: wire format; `defs.py` is the schema source, `writer.py` and `reader.py` the codecs. `emitters/codegen.py` generates C, `emitters/yaml.py` the plan YAML.
- `src/tigris/capabilities.py`: per-operator backend routes, constraints and conditional fallbacks; the public matrix JSON is generated from it.
- `src/tigris/__init__.py`: `SCHEMA_VERSION` and `SUPPORTED_SCHEMA_VERSIONS` live here. `compatibility.json` records compiler and runtime releases with the schemas each emits or accepts, and an entry names whichever component was cut, since the two release independently. `tests/schema_compat/` holds a frozen plan for every supported schema version.

## Gotchas
- Normalize pass order is fixed in `normalize()`: constant fold, QDQ fold, BN fold, SiLU decompose, depthwise relabel, Conv1D relabel, Clip(0,6) to Relu6, ReduceMean to GlobalAveragePool, shape-op fold, Resize scale extraction, Concat axis, transpose validation, activation absorption last. Constant folding must run before QDQ folding because scale and zero-point inputs arrive as Constant ops.
- The IR keeps ONNX NCHW/NCL shapes; the runtime executes NHWC/NLC. The switch happens at emission in `writer.py`: Conv weights are transposed, depthwise weights stored HWC, FC weight columns permuted after a Flatten, and the normalizer remaps the Concat axis.
- Bumping the plan schema touches `defs.py`, `SCHEMA_VERSION`, a regenerated `src/tigris/schema/tigris-plan-vN.json`, a new frozen plan in `tests/schema_compat/`, and `compatibility.json`.
- The version comes from git tags via setuptools-scm (`src/tigris/_version.py` is generated); a shallow clone reports a wrong version, so CI uses `fetch-depth: 0`.

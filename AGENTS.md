# tigris

Ahead-of-time compiler that tiles ONNX and TFLite models to fit a memory budget and emits `.tgrs` binary plans plus C harnesses for the tigris-runtime. Python (floor in `pyproject.toml`), click CLI, setuptools-scm versioning. Public, github.com/raws-labs/tigris; on PyPI as `tigris-ml`.

## Build, test, run
- `pip install -e ".[dev]"`: editable install with pytest, onnxruntime, ruff, build.
- `pytest`: tests under `tests/`; `conftest.py` builds small hand-crafted ONNX graphs, so no model download is needed. `scripts/` is an importable package (has `__init__.py`, and pytest puts the repository root on `sys.path`) because the tests import from it, `conftest.py` included; it is not shipped in the wheel.
- `ruff check src tests scripts`: rule set is pinned to `E4, E7, E9, F` in pyproject so a ruff upgrade does not change CI policy.
- `python -m build`: source distribution and pure wheel. Native wheels require staging with `scripts/runtime_bundle.py` and `TIGRIS_WHEEL_VARIANT=native`; see `CONTRIBUTING.md`. CI installs both variants outside the checkout and tests their CLI behavior.
- Generated artifacts: `src/tigris/schema/tigris-plan-v<SCHEMA_VERSION>.json` (from `emitters/binary/defs.py`) and `src/tigris/schema/operator-capabilities-v1.json` (from `capabilities.py`). `tests/test_release_compatibility.py` compares each file's text with its generator; `python scripts/generate_schema_package.py --output PATH` and `python scripts/generate_capability_matrix.py --output PATH` rewrite them. `python scripts/generate_operator_contract.py --runtime <path to a tigris-runtime checkout>` writes the runtime's generated headers `src/tigris_op_contract.h` and `src/tigris_op_config.h` from `operator_contract.py`.
- Cross-repo gates, each taking `--runtime <path to a tigris-runtime checkout>`: `scripts/crossrepo_contract.py` (compiler plans executed by the runtime's contract runner against ONNX Runtime, float32 and s8 reference dispatchers only), `scripts/validate_compatibility.py` (`compatibility.json` vs the runtime's `TIGRIS_SCHEMA_VERSION*` macros), `scripts/validate_runtime_capabilities.py` (capability matrix vs the runtime dispatch switches, and the runtime's generated operator headers vs the generator). CI runs the contract gate as its own step and the two validators through `tests/test_release_compatibility.py`; it checks out the runtime's `develop`, or a same-named branch when one exists.
- Tests that run TFLite Micro need `tflite-micro` from the dev extra (Linux x86_64 wheels only): missing, they skip, but fail when `CI` is set.
- Runtime-dependent tests: `tests/test_codegen_c_syntax.py` compiles generated C against the runtime headers, found through `TIGRIS_RUNTIME_SOURCE` or a sibling `tigris-runtime` checkout; the host-library tests need the library staged in `src/tigris/native` by `scripts/runtime_bundle.py --source <runtime>`. Missing prerequisites skip, but fail when `TIGRIS_RUNTIME_SOURCE` or `CI` is set (headers) or `TIGRIS_REQUIRE_HOST=1` (host library); CI sets all three.

## CLI
- Subcommands: `analyze` (fit against a budget, `--json` report, `--trace` runs the plan on the host runtime and prints every load, spill and tile), `compile` (binary `.tgrs`, prints the same summary), `codegen` (C from a `.tgrs`), `export` (a TFLite model rewritten so TFLite Micro runs it in a smaller arena; nothing is written when no rewrite lowers it), `inspect` (file contents and costs, no compilation), `run`, `zoo`.
- Output is plain text through `cli/text.py`: click styles, `NO_COLOR` honored, no color off a terminal. One blank line between sections, none before the first.
- Budgets: first `-m` is the fast pool, a second `-m` the slow pool; `-m 256K+4M` is sugar for `-m 256K -m 4M`. `-f/--flash` makes `compile` fail when the plan exceeds it. `--xip` reads weights in place from flash. `-c lz4` compresses weight blocks.
- `codegen --backend reference|esp-nn|cmsis-nn --format app|core`; `--header` and `--name` are valid only with `core`. Accelerated backends are int8 only; a float32 plan on them gets the reference dispatcher explicitly.
- `export --target arm-none-eabi|ilp32|lp64` (default `arm-none-eabi`): the C ABI of the TFLite Micro build whose arena decides whether a rewrite is written.

## Layout
- `src/tigris/frontends/`: TFLite import, converted to the compiler's QDQ ONNX form. `tflite_writer.py` reads a TFLite file into records and writes it back with the FlatBuffers builder; `tflite_export.py` holds the row-band rewrite behind `export`; `tflite_schema.py` holds the schema's field slots and name tables that `tflite.py`, the writer and export share. `tflm.py` models TFLite Micro's arena on reference kernels: `tflm_arena` the planner head, `tflm_persistent` the persistent tail record by record, transcribed from the TFLite Micro sources the dev-extra `tflite-micro` is built from; tests compare it with the tail that package measures on each pinned model, so a pin bump that moves one of those tails fails them. `src/tigris/loaders/onnx/`: ONNX import; the `normalize/` package holds the pass pipeline for both, one module per concern.
- `src/tigris/analysis/`: lifetime, memory model, temporal partition (stages), spatial partition (tiles, chains, 2D tiling), validation.
- `src/tigris/emitters/binary/`: wire format; `defs.py` is the schema source, `writer.py` and `reader.py` the codecs. `emitters/codegen.py` generates C.
- `src/tigris/capabilities.py`: per-operator backend routes, constraints and conditional fallbacks; the public matrix JSON is generated from it.
- `src/tigris/__init__.py`: `SCHEMA_VERSION` and `SUPPORTED_SCHEMA_VERSIONS` live here. `compatibility.json` records compiler and runtime releases with the schemas each emits or accepts, and entries record each component separately. Paired releases share a version; release ordering and version checks are in `CONTRIBUTING.md`. `tests/schema_compat/` holds a frozen plan for every supported schema version.

## Gotchas
- Normalize pass order is fixed in `normalize()` in `loaders/onnx/normalize/__init__.py`. The loader turns every Constant node into a constant, in subgraphs too, so no pass sees a Constant operator; `shapes.static_value` is the one evaluator for values the graph settles before it runs, used by the load-time fold and `_fold_static_subgraphs`.
- The IR keeps ONNX NCHW/NCL shapes; the runtime executes NHWC/NLC. The switch happens at emission in `writer.py`: Conv weights are transposed, depthwise weights stored HWC, FC weight columns permuted after a Flatten, and the normalizer remaps the Concat axis.
- Bumping the plan schema touches `defs.py`, `SCHEMA_VERSION`, a regenerated `src/tigris/schema/tigris-plan-vN.json`, a new frozen plan in `tests/schema_compat/`, and `compatibility.json`.
- The version comes from git tags via setuptools-scm (`src/tigris/_version.py` is generated); a shallow clone reports a wrong version, so CI uses `fetch-depth: 0`.
